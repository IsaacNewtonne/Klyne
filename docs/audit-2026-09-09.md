# Project audit — 2026-09-09

Scope: workspace structure and documentation, complete test/build/lint checks,
file benchmarks, and targeted code review of delegation, browser transport,
and network fetch. This is not an exhaustive security assessment.

## Implemented in this pass

- High: child IDs were interpolated directly into SQLite paths. Reject empty,
  overlong, traversal, separator and punctuation-bearing IDs before creating
  child directories or databases. IDs now use 1–128 ASCII letters, digits,
  hyphens or underscores. Require the supplied parent root to match its policy.
- High: read-only children could be given shell authority, allowing writes
  despite revoking the filesystem-write capability. Reject shell grants for
  read-only children before side effects.
- Medium: artifact reads checked metadata then performed an unlimited read.
  Cap the actual read at the configured limit plus one detection byte, and
  reject overflow. Concurrent path replacement and hard links remain outside
  this protection.
- High: fragmented WebSocket messages checked aggregate size only on their
  final frame. Reject overflowing fragment lengths before payload allocation
  or reading. Also cap upgrade headers at 16 KiB.
- Added six regression tests covering rejection before side effects, fragmented
  overflow without a final frame, exact-limit fragments with interleaved ping,
  and oversized upgrade headers.

## Remaining findings and next development priorities

1. Browser lifecycle (`browser.rs`): a failed page connection after spawn can
   leave an owned Chrome process running. Drop does not remove disposable
   profiles; explicit close repeats termination when Drop runs. Introduce an
   owned-session cleanup guard and test failure paths before adding GUI control.
2. Browser HTTP (`cdp.rs`): response headers/body lack explicit size caps;
   missing/invalid Content-Length defaults to zero. Bound and strictly frame
   responses, and enforce a single end-to-end I/O deadline.
3. Browser protocol (`cdp.rs`, `ws.rs`): load events received during a call are
   discarded; future response IDs are parked and can satisfy calls before
   sending them. Replace this with bounded event handling and strict response
   correlation. Validate loopback debugger targets and the upgrade handshake;
   transport currently does not verify Sec-WebSocket-Accept.
4. Delegation budgets are caller-supplied snapshots, not an atomic parent-owned
   reservation pool. Concurrent children and inherited time/token/cost limits
   remain incomplete. Runtime state paths also require a separate symlink and
   reparse-point audit.
5. GUI control remains planned. Existing milestone labels describe prototype
   feature coverage, not completed production hardening.
