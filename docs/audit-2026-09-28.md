## Initial findings

### A1 — High: New Chat retains the previous host project and execution settings

**Locations:** `apps/studio/web/chat.js:152–160`, `apps/studio/web/chat.js:189`, `apps/studio/src/chat.rs:646–658`.

Selecting an existing conversation loads its project folder, access flags, step limit, timeout, and review limit. `select(null)` resets only command policy, token limit, and spend limit. The next submission includes the retained project folder and access flags, and the server accepts that folder as the new conversation's workspace.

**Reproduction:** open a conversation with Terminal enabled, a host project, a 25-step limit, and a 30-second timeout; click New Chat. The project folder remains `C:\projects\previous-project`, Terminal remains enabled, and the limits remain 25 and 30. This was reproduced against the actual presentation code with a synthetic conversation fixture.

**Impact:** an unrelated new task can read or change the previous project using the ordinary workspace file tools. Exact-command approval does not protect those file writes. The welcome screen does not make this inherited destination clear. Turning Terminal off while retaining the folder also causes subsequent sends to fail with `Host workspace selection requires Terminal`.

**Correction:** define explicit new-conversation defaults; clear the project selection and conversation-specific limits when creating a new chat, or make intentional inheritance visible before submission. Do not submit a host workspace when Terminal is disabled. Add a select-existing → New Chat → submit regression test that inspects the submitted destination.

### A2 — Medium: switching providers destroys saved settings

**Locations:** `apps/studio/web/chat.js:203–214`; equivalent behavior in `apps/studio/web/app.js:136–158`.

The provider change handler calls `configureProvider()` with no saved configuration. That function resets the endpoint and model, then immediately overwrites the shared localStorage record.

**Reproduction:** choose Ollama, enter `audit-model`, switch to Codex, and switch back. The stored model changes from `audit-model` to an empty string. A custom endpoint is likewise replaced by the default.

**Impact:** browsing connector choices loses working configuration and can prevent sending until the user configures the model again. Reloading then restores the already-erased values. This is specifically a switching defect; an ordinary reload without switching was not established to be broken.

**Correction:** store configuration per provider and restore it on selection. Preserve the selected provider separately. Test toggling and reloading as separate scenarios.

### A3 — Medium: trusted-laptop preference only partially survives reload

**Locations:** `apps/studio/web/chat.js:314–321`, `apps/studio/web/chat.js:156`.

The trusted-laptop button enables four access flags and sets command policy to `autonomous`, but its saved preference restores only the access flags. Reload leaves Terminal enabled with policy `ask`. New Chat also unconditionally resets that policy to `ask`.

**Reproduction:** click Enable trusted laptop access and reload. Observed policy: `autonomous` before reload, `ask` afterward; Terminal remains enabled.

**Impact:** the advertised one-time setup produces repeated command approval prompts after reload or New Chat.

**Correction:** decide whether the preference applies globally or only to one conversation, persist its full intended state, and make the button copy match that scope. Preserve explicit per-conversation overrides.

### A4 — Medium: the tracked browser regression gate is intermittent

**Location:** `apps/studio/tests/chat.rs:1935–1938`.

The unrestricted full run failed `production_view_tracks_real_model_workers_evidence_and_result` at its 390×844 overflow assertion. An isolated rerun of the same test passed. A separate settled mobile fixture also showed document width 390 and production scroll/client widths both 366.

**Impact:** the current test gate is not repeatably green. The evidence does not establish a persistent mobile layout bug or identify which half of the original combined assertion failed.

**Correction:** capture both widths, overflowing element rectangles, screenshot, transition state, and browser errors at failure. Wait for the resize/transition state the assertion intends to measure; then determine whether the remaining problem is layout or synchronization. Do not delete the assertion or label the initial failure a pass.

### A5 — Medium: deployment has no automated regression gate

**Location:** `.github/workflows/pages.yml` (the only workflow in this checkout).

The workflow builds and deploys the static demo but runs no Rust tests, JavaScript UI checks, Python recovery tests, formatting, or Clippy. The locally observed failures would not block this deployment.

**Correction:** add a reproducible deterministic CI tier, and a Windows/browser gate for the supported platform. Keep GUI and live integration tiers explicit. The JavaScript checks currently depend on Playwright under ignored `workspace/studio/conversations/mcp-packages/node_modules`, so a clean runner also needs a documented, pinned installation path.

### A6 — Low: formatting and strict Clippy checks fail

**Locations:** multiple Rust files; strict Clippy stops at `apps/studio/src/performance.rs:240`.

`cargo fmt --all -- --check` reports formatting differences in tracked source and tests as well as the pre-existing untracked test. `cargo clippy --locked --workspace --all-targets -- -D warnings` fails on `field_reassign_with_default` in the performance test.

**Correction:** format the tracked Rust files and initialize the test trace with the relevant field in its initializer. Make both checks part of CI. These findings alone do not imply a runtime defect.

## Pre-existing untracked test issue

`apps/studio/tests/settings_repro.rs` existed before this audit and was left unchanged. It fails at line 50 because repeated CDP evaluations declare top-level `const k` in the same JavaScript context. It therefore never reaches its intended persistence assertion. Use an IIFE or another local scope for each evaluation.

Its server cleanup occurs only after the failing operations, so a panic leaks the disposable Studio process. Use a drop guard for the child process. The leaked audit server was identified by its executable, port, and temporary root for cleanup. The independent UI reproduction used a `finally` block and confirmed A2 without relying on this failing test.
