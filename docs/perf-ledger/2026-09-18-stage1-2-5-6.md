## Experiment 1 — Stage-1 trace (IDs, stage timers, milestones)

- Predicted: every goal carries `req-<n>`; every model attempt, tool
  execution and persisted observation gets a unique ID; stage timers
  attribute preparation / model-request / tool-execution / verification /
  db-checkpoint; milestones record first feedback, first action, verified
  completion. No prompt text recorded.
- Change: `performance.rs` (`Trace`, `ToolSample`, `ObservationSample`,
  `report()`), wired into `chat.rs` (`request`/`action`/`save`/`drive`),
  `chat_store::pulse` reuses `report()`.
- Measured (deterministic fixtures, `tests/perf.rs`): greeting = 1 model
  call, 0 tool calls, first-feedback milestone set, first-action null;
  verified file task = 3 model calls, unique model/tool/observation IDs,
  write_file + read-back timings present, all milestones set.
- Wall-clock durations in fixtures are environment-specific (instant
  stub model) — structure is exact, durations are not benchmarks.

## Experiment 2 — Stage-2 host-contract review skip

- Predicted: verified file task goes 4 model calls → 3; unverified
  contracts, desktop outcomes, pending work and approval queues keep model
  review.
- Change: fast path in `drive_inner` (all tasks Done + evidence-bound +
  verified acceptance contract + no desktop-outcome requirement).
- Measured: `contract_verifies_actual_file` and
  `restart_reconciles_saved_document` both 4 → 3 calls, outcome still
  `verified`. Two existing tests updated (reply queues shortened).
- Negative check: `contract_rejects_model_success_without_the_requested_artifact`
  still fails verification and keeps model review (unchanged).

## Experiment 3 — Stage-5 pulse endpoint + seq UI refresh

- Predicted: idle 1.5 s polls stop fetching full snapshots; any status/seq
  change or pulse failure falls back to full fetch.
- Change: `GET /api/chats/:id/pulse?since=N` (one-row read, `serve_ms`
  self-reported); `chat.js` refresh compares seq/status first.
- Measured: `pulse_endpoint_serves_sequenced_events_with_trace` passes
  (seq advances, empty on no-change, unknown id errors); `node --check`
  clean; activity JS suite passes. No SSE — polling retained as the
  fallback, per plan. Loopback-only timing; no <200 ms UI claim made.

## Experiment 4 — Stage-6 shared HTTP transport

- Predicted: connection reuse across model/API calls; deadlines, caps,
  redirect policy and cancellation unchanged.
- Change: `network.rs` shares one multi-thread runtime + one client
  (`rt-multi-thread` feature); timeout moved to per-request.
- Measured: existing cancellation test passes; new
  `shared_transport_serves_repeated_calls` passes. No setup-cost split
  measured yet — follow-up.
